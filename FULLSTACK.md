# «Лист» — единое приложение библиотеки

## Запуск

Из корня проекта, с установленным Docker Desktop и работающим **Linux engine**:

```powershell
# Только если .env ещё отсутствует:
python scripts/configure.py

docker compose up -d --build
docker compose ps
docker compose logs migrate
docker compose exec auth python scripts/admin.py
```

В этой папке `.env` уже создан со случайными секретами. Скрипт отказывается его перезаписывать. Без Python создайте `.env` из `.env.example` и задайте секреты вручную, как описано в README.

Откройте **http://localhost:8080**. Фронтенд собирается внутри Docker и раздаётся Nginx gateway, который также проксирует API микросервисов. Для этого запуска Node/Python на хосте не нужны. PostgreSQL и веса модели сохраняются в томах. Остановка с сохранением данных: `docker compose down`; обновление: `docker compose up -d --build`.

Первого администратора создаёт интерактивный `scripts/admin.py`. После входа он может назначить сотрудников в разделе «Пользователи». Читатели регистрируются в интерфейсе. Тестовые письма доступны в Mailpit: http://localhost:8025. Для реальной почты настройте SMTP согласно README.

## Книги и настоящие рекомендации

Первый запуск создаёт пустую библиотеку. В разделе «Управление» сотрудник добавляет авторов, жанры, книги и физические экземпляры. Книга без экземпляров видна в каталоге, но забронировать её нельзя. После сохранения/изменения/архивирования книги фронтенд запускает обновление нейросетевого индекса. При ошибке можно повторить его кнопкой «Обновить рекомендации».

Для нового демонстрационного окружения можно добавить восемь классических книг с экземплярами через реальные API:

```powershell
docker compose exec auth python scripts/demo.py
```

Скрипт спросит почту и пароль администратора/сотрудника, добавит описания, авторов, жанры и экземпляры, затем построит **настоящий** векторный индекс. Существующие книги не перезаписываются. Это необязательные данные в PostgreSQL, а не встроенные заглушки интерфейса.

При первом обновлении индекса скачивается многоязычная модель Sentence Transformers на PyTorch. Нужны интернет и свободное место. Используется CPU-сборка PyTorch. На медленном соединении загрузка может превысить 5-минутный таймаут; проверьте `docker compose logs recommendations`, дождитесь загрузки и повторите обновление.

В кабинете подборки получаются из `/recommendations/me?interests=…`, а поиск по смыслу — из `/recommendations/search`. Бэкенд рассчитывает embedding и ищет близкие векторы в pgvector. Даже подборка нового читателя проходит через нейросеть: по интересам либо стартовому литературному запросу. Все результаты имеют численный cosine score. Если индекс не готов или сервис недоступен, интерфейс показывает ошибку, не подменяя рекомендации общим каталогом. При изменении книг через API напрямую переиндексацию вызывайте самостоятельно.

## Экраны и роли

| Роль | Возможности |
|---|---|
| Посетитель | Открытый каталог, пагинация, фильтр жанра, поиск по названию и смыслу, описания книг, доступность экземпляров на выбранные даты |
| Читатель | Регистрация/вход/выход, бронь экземпляра, свои брони и выдачи, история, отмена с подтверждением, статусы просрочек, нейросетевые подборки |
| Сотрудник | CRUD книг/авторов/жанров, экземпляры и списание, поиск броней, выдача, возврат, отмена, обновление рекомендаций |
| Администратор | Все возможности сотрудника, роли пользователей, блокировка и восстановление доступа |

Все разрешения проверяет бэкенд. Даты вводятся в часовом поясе устройства и отправляются в UTC. Максимальный период — 60 дней. При занятом интервале форма показывает конфликт и повторно загружает доступность. Сотрудник может выдать экземпляр только во время активной брони. Блокировка/смена роли отзывает сессии пользователя; нельзя отключить последнего активного администратора.

JWT хранится в `sessionStorage`: сохраняется после обновления страницы в той же вкладке. При 401 предлагается повторный вход. Logout отзывает токены на сервере; при сетевой ошибке интерфейс оставляет возможность повторить запрос. Пароли не сохраняются. Читательские интересы хранятся в `localStorage` браузера с привязкой к ID пользователя.

## Разработка фронтенда

Node.js 22.12+ (рекомендуется 24), npm. Бэкенд должен работать через gateway на порту 8080.

```powershell
cd frontend
npm ci
npm run dev
```

Dev-сервер: http://127.0.0.1:5173. Vite проксирует API на `http://127.0.0.1:8080`, поэтому отдельный CORS не нужен. Для другого API задайте `API_PROXY_TARGET` перед запуском Vite. Не помещайте секреты в `VITE_*`: они попадают в клиентскую сборку.

`npm run build` проверяет TypeScript и создаёт production-сборку. `npm run preview` показывает статическую сборку; для операций с API используйте dev-сервер с proxy или Docker gateway.

## Тесты интерфейса

```powershell
cd frontend
npm ci
npx playwright install chromium
npm run build
npm test
```

`ui.spec.ts` проверяет React с контролируемыми HTTP-ответами: открытый каталог, регистрацию, авторизованные запросы, конфликт/отмену брони, нейросетевые API, ошибку рекомендаций, роли и истечение сессии. Каждый сценарий выполняется на desktop и mobile Chromium. Это проверка интерфейса, а не доказательство работы PostgreSQL или весов модели. HTML-отчёт: `frontend/playwright-report/index.html`, трассы ошибок: `frontend/test-results/`.

## Браузерный тест всего стека

`live.spec.ts` работает с настоящими сервисами, создаёт данные и загружает модель. Запускайте **только на отдельном тестовом стеке**. Обычный стек нужно остановить, чтобы освободить порты; его тома сохранятся.

```powershell
# Из корня:
docker compose down
docker compose -p library-test -f compose.yaml -f compose.test.yaml up -d --build gateway notifications mailpit
docker compose -p library-test exec auth python scripts/admin.py

cd frontend
$env:E2E_ADMIN_EMAIL = 'test-admin@example.com'
$env:E2E_ADMIN_PASSWORD = 'Your-test-admin-password-123!'
npm run test:live
Remove-Item Env:E2E_ADMIN_EMAIL
Remove-Item Env:E2E_ADMIN_PASSWORD
```

Введите данные администратора, которого создали на тестовом стеке. Указанный пароль — шаблон. Другой адрес задаётся через `LIVE_BASE_URL`. Live-тест подтверждает регистрацию, бронь, отмену и настоящую нейросетевую выдачу с численными scores. В нём нет route mocks.

Для CI на изолированном стеке есть `scripts/ci_admin.py`, который требует явный `ALLOW_CI_ADMIN=true` и создаёт известные тестовые учётные данные. Никогда не запускайте его на рабочих данных. GitHub Actions собирает frontend, запускает UI-тесты, интеграционные тесты с моделью и live-сценарий. Интеграционные проверки SMTP и конкурентных броней описаны в README.

## Развёртывание

1. Linux-сервер с Docker/Compose, production `.env`, резервными копиями и SMTP. Собирайте и тестируйте образы в CI; публикуйте их в registry с фиксированными digest.
2. Внешний TLS reverse proxy направляет запросы на `127.0.0.1:8080`. Фронтенд и API используют один домен, например `https://library.example.com`.
3. Многостадийный `frontend/Dockerfile` собирает React в Node-контейнере, а готовые файлы переносит в Nginx. Node отсутствует в финальном контейнере gateway.
4. Запустите миграции и сервисы, создайте первого администратора, наполните каталог и подготовьте AI-индекс. Настройте реальный SMTP и уберите Mailpit.
5. Nginx кеширует `/assets/`, не кеширует `index.html`, блокирует `/internal/*`. Добавлены CSP, Referrer-Policy и `nosniff`. `/health` gateway проверяет Nginx, а не всё приложение.
6. Контролируйте сервисы, очереди писем и актуальность индекса; выполняйте резервные копии и проверяйте восстановление. База и миграции подробнее описаны в README.

Шрифты имеют системные fallback; текущий CSS дополнительно запрашивает Golos Text и Lora у Google Fonts. Если внешние шрифты запрещены, удалите `@import` или разместите файлы локально и адаптируйте CSP.
